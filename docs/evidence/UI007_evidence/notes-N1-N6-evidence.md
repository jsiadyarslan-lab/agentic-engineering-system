## N-1 (العودة الحقيقية الوحيدة) — فرض LTR كامل السطر على `.pv-meta` / `.task-evidence`

**المشكلة:** عزل BiDi كان يُطبق على السطر كاملًا فيخبط ترتيب العربية+اللاتينية.
**المعالجة:** الاتجاه rtl للسطر + عزل `dir=ltr` على القيم التقنية فقط (`.tech` / `code`).

**الدليل القابل للتكرار:**
- حي (`browser-session.txt` [R3]): `pv-meta direction/font: "rtl | \"IBM Plex Sans Arabic\"…"` — السطر عربي RTL.
- حي: `pv-meta code dir attr: "ltr"` — القيم التقنية معزولة الاتجاه.
- حي: `pv-meta sample: "المعرف: nvidia · النوع: nvidia · المصادقة: bearer"` — الترتيب سليم.
- ساكن: `rg -n "\.tech" src/ui/theme.css` → القاعدة `308: .tech, .md-code, code, pre` (عزل `unicode-bidi: isolate`).

## N-2 — قيمة z حرفية `60` على `.pl-plan-modal` (تحت درج 61)

**المعالجة:** `z-index: var(--z-modal)`.

**الدليل:**
- ساكن (`static-checks.txt` §4): **صفر قيم z حرفية** في كل ملفات CSS UI بعد تجريد التعليقات.
- ساكن: `project-live.css:281: z-index: var(--z-modal);` مع تعليق موثق داخل الكود «(007 N-2) آخر قيمة حرفية في النظام».
- حي: `--z-modal` المحسوب في DOM = `70` (سلّم واحد معلن في theme.css:142).

## N-3 — خط تبويب المصنع أزرق يخالف قاعدة التبويب الواحد + أول عرض بلا active

**المعالجة:** التبويب النشط ذهبي بنفس قاعدة settings-tab/pl-tab؛ وأول عرض للتبويبات بلا active.

**الدليل:**
- حي ([R5]): `first-render active fc-tabs: 0` — أول عرض بلا active ✓.
- حي: `active tab underline color: "rgb(212, 172, 85)"` = الذهبي المؤسسي `--accent` ✓.
- حي: `active tab text color: "rgb(240, 243, 246)"` — نص النشط فاتح.
- حي: `factory bg computed: "rgb(13, 16, 20)"` — سطح المصنع من فحم النظام (كان جزيرة كحلية rgb(11,14,20)).

## N-4 — دلالة ألوان النقاط متناقضة بين الأسطح

**المعالجة:** مفردة واحدة: حي = أزرق الوكيل النابض (`--accent-agent`)، مكتمل = أخضر، منتظر = كهرماني، فاشل = أحمر.

**الدليل:**
- ساكن: `theme.css:231: .status-dot.live { background: var(--accent-agent); }` — النقطة الحية أزرق الوكيل.
- ساكن (التوصيل): `factory-control.css:34: --acc: var(--accent-agent)` — أزرق المصنع أصبح **استهلاكًا للرمز الدلالي** لا لوحة موازية.
- حي ([R6]): الرموز المحسوبة في DOM: `--accent-agent #58A6FF / --ok #5CB87A / --warn #D9A03F / --danger #E06C5F`.
- **قيد معلن:** لا نقطة «حي» مرسومة في جلسة إعادة الإثبات (لا يوجد وكيل نشط — الحالة الفارغة صادقة)، فالدلالة مثبتة بالتوصيل البرمجي والقاعدة، ويُنتظر أول تشغيل حقيقي لإظهارها حية.

## N-5 — انحراف 6px بين المحرر والرسائل

**المعالجة:** شبكة عرض موحدة.

**الدليل:**

## N-6 — `.eb-btn` أبيض/أحمر ~2.9:1 + مداخل mono حرفية

**المعالجة:** خلفية أدكن (color-mix) + `var(--font-mono)`.

**الدليل:**
- محسوبًا من التصريح (`static-checks.txt` §6): `#fff` على `color-mix(in srgb, var(--danger) 82%, black)` = `#b8594e` → **4.59:1 (AA ✓)** للنص 12px/600.
- ساكن: `--font-mono` معلن مرة في theme.css:83 ومستهلك في 8 ملفات (25 استعمالًا).
- **قيد معلن:** زر الطوارئ غير قابل للتوليد في حالة الفحص (سياقه فشل تشغيل نشط) — مثبت بالحساب من التصريح لا بلقطة.
- حي (دليل مرتبط): بطاقة الخطأ بلا مزود تعمل: «تعذر إكمال الطلب — السبب: المزود 'nvidia' غير متاح للربط الحي — المتاح: ['zai_internal']…» (`browser-session-extra.txt` [X2]).
