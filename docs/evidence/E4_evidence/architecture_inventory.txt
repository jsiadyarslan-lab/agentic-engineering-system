E4 ARCHITECTURE INVENTORY
=========================

CURRENT_AGENT_MODEL:
- Two separate systems:
  1. AgentFactory (src/factory/agents/): 8 agents (Explorer, Thinker, Planner, Designer, Reviewer, Implementer, Verifier, Security)
     - BaseAgent with LLM, SharedContextManager, GrantManager
     - AgentTask/AgentResult from factory contracts
  2. EAS v2 (src/roles/): 5 roles (Thinker, Reviewer, Implementer, Verifier, Arbiter)
     - LiveRoleBase with ModelRouter, prompt files
     - Cycle: THINKER -> REVIEWER -> IMPLEMENTER -> VERIFIER -> ARBITER
  3. Unified (src/unified/): AgentRole protocol, AgentRegistry, AgentFactory
     - AgentType enum: EXPLORER, ANALYST, PLANNER, DESIGNER, REVIEWER, IMPLEMENTER, VERIFIER, ARBITER
     - AgentCapability with tools, permissions, max_tokens, timeout
     - AgentContext for runtime
     - AgentRole protocol (on_start, execute, on_complete, on_failed)
     - BaseAgent with event emission, budget, grants, sandbox helpers
     - AgentRegistry: register/unregister/get_class/create_instance/list_registered
     - AgentFactory: create_agent + execute_agent with validation
     - EASRoleAdapter for wrapping EAS v2 roles
     - AgentContractRegistry with input/output/acceptance for each type

CURRENT_AGENT_STORAGE:
- AgentRegistry._agents: Dict[AgentType, Type[AgentRole]] (in-memory)
- AgentRegistry._instances: Dict[str, AgentRole] (in-memory)
- Agent domain model exists but not persisted
- No persistent storage for agent definitions

CURRENT_AGENT_DISCOVERY:
- AgentRegistry.list_registered() returns list of AgentType
- AgentRegistry.validate_all_registered() checks all 8 types
- No capability-based discovery

CURRENT_AGENT_SELECTION:
- Hardcoded in Orchestrator._REQUIRED_ROLES (5 EAS roles)
- Hardcoded in wiring.py build_*_orchestrator
- No capability matching, no policy check

CURRENT_AGENT_EXECUTION:
- EAS: Orchestrator.run_cycle() calls role.run() sequentially
- AgentFactory: execute_agent() calls on_start -> execute -> on_complete/on_failed
- Unified: AgentFactory.execute_agent() with AgentContext
- ExecutionEngine: uses AgentRole protocol but no agent selection logic

CURRENT_AGENT_TOOL_BINDING:
- AgentCapability.tools lists allowed tool names
- AGENT_CAPABILITIES dict maps AgentType -> AgentCapability
- BaseAgent._run_in_sandbox, _write_artifact, _read_artifact for sandbox ops
- No enforcement of tool permissions at execution time

CURRENT_AGENT_STATE:
- Agent domain model: state in [idle, working, blocked, completed, failed]
- No state machine enforcement
- No lifecycle transitions validation

CURRENT_AGENT_LIFECYCLE:
- BaseAgent: on_start -> execute -> on_complete/on_failed
- Event emission: AGENT_STARTED, AGENT_COMPLETED, AGENT_FAILED
- No REGISTERED/AVAILABLE/ASSIGNED/DISABLED states

MISSING_COMPONENTS:
1. Agent Definition contract (serializable, versioned, validated)
2. Persistent Agent Registry (or at least clear contract)
3. Capability-based agent selection (deterministic)
4. Tool permission enforcement at execution
5. Agent lifecycle state machine (REGISTERED -> AVAILABLE -> ASSIGNED -> RUNNING -> COMPLETED/FAILED -> DISABLED)
6. Disabled agent enforcement
7. Unknown agent rejection
8. Version resolution
9. VS-003: End-to-end test with real agent lifecycle
10. Agent failure history preservation
