# OPS-GZIP-1112 — ضغط gzip في nginx لعاصفة 499 على واجهة القاعة

التاريخ: 2026-11-12 00:45 GMT · المصدر: جلسة تشخيص حية من سجل الوصول الفعلي

## العرَض

متصفح المالك (2.215.157.88) يفتح `http://92.5.14.150/` — قاعة التحكم تُعرض
هيكلها بينما تدور جميع البطاقات (طابور القرارات/أرضية المصنع/العدادات/المشاريع)
في «جارٍ الجلب…» إلى الأبد. سجل nginx أظهر عاصفة إجهاض عند 2026-11-12 00:33:

- `GET /api/projects/3/state` → عشرات الطلبات بحالة **499** (المتصفح أغلق قبل الرد)
- طلب واحد اكتمل بحجم **2,233,359 بايت** خاماً
- `GET /api/projects/runs/active` (2KB فقط) أُجهض أيضاً خنقاً

## السبب الجذري (قياس لا تخمين)

- `/api/projects/3/state` = **2.23MB** غير مضغوطة (P3: 958 خطوة/288 بوابة)
- HTTP/1.1 يمنح المتصفح **6 اتصالات** لكل origin — اللقطة الضخمة تلتهمها كلها
  عشرات الثواني، فيُصفّ كل طلب API آخر حتى انتهاء مهلة الواجهة (25s abort)
- الخلفية نفسها سليمة 100%: قياس محلي `/state` = 0.21s، وكل البقية < 0.07s

## الإصلاح

تمكين ضغط gzip في `conf.d/agentic.conf` (مستوى كتلة server — يشمل كل المواقع):

```nginx
gzip on;
gzip_proxied any;
gzip_vary on;
gzip_min_length 1024;
gzip_comp_level 6;
gzip_types application/json text/plain text/css text/javascript application/javascript image/svg+xml;
```

- لا تغيير في عقود API ولا في الواجهة ولا في الخلفية — السلك فقط
- موقع اختبار مؤقت `return 200` تحقق من `Content-Encoding: gzip` فعلياً ثم أُزيل

## القياس بعد التثبيت

| الحمولة | قبل | بعد gzip |
|---|---|---|
| `/api/projects/3/state` | 2,233,359 B | **365,672 B (16.4%)** |

- `nginx -t` PASS قبل/بعد، `systemctl reload nginx` مرتين بلا انقطاع
- `/healthz-*` = 200 خارجياً بعد التغيير
- النسخة الاحتياطية: `conf.d/agentic.conf.pre-gzip-1112.bak`

## أثر متوقع

زمن حمل الشاشة الرئيسية على خط المالك يهبط ~6x، اتصالات HTTP/1.1 تتحرر فوراً،
وتتوقف عواصف 499. للمستخدم: تحديث قسري (Ctrl+F5) يكفي.
