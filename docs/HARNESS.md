# طبقة الـEngineering Harness (الأمر التنفيذي 012)

> دليل معماري — كيف تحوّل النظام من «تطبيق برؤية هندسية» إلى
> **Harness هندسي**: طبقتان واضحتان، قدرة قابلة للتركيب، وظيفة
> دائمة قابلة للنبض والانقطاع والاستئناف، ومنسق حتمي بلا LLM.
> خط الأساس: الأمر 011 (b21f12d) لم يُمس — كل شيء هنا فوقه.

## الفكرتان المعماريتان

### 1. فصل الطبقتين

```
┌──────────────────────────────────────────────┐
│      AGENTIC ENGINEERING LAYER (012)         │
│                                              │
│  EngineeringJob — الوظيفة الدائمة (نبضة،     │
│  انتظار صادق، انقطاع، استئناف)               │
│  coordinator — المنسق الحتمي (لا LLM)         │
│  roles_runtime — الأدوار ككيانات أولى        │
│  projections — خط زمن + سلسلة قبول           │
└──────────────────┬───────────────────────────┘
                   │ يستهلك حصرًا عبر
┌──────────────────▼───────────────────────────┐
│      HARNESS SEAMS — الدروز (seams.py)       │
└──────────────────┬───────────────────────────┘
                   │ يفوّض إلى (لا يستبدل)
┌──────────────────▼───────────────────────────┐
│      011 TRUTH + BACKENDS                    │
│  readiness/service — مصدر الحقيقة الوحيد     │
│  execution/service — resolve_executor واحد   │
│  research/service — سلسلة مزودين بفشل مفصل   │
│  providers_registry — ربط الأدوار الدائم     │
│  workflow/engine — آلة حالة المشروع          │
└──────────────────────────────────────────────┘
```

الدرزة ليست إعادة كتابة؛ هي **حدّ معماري معلن**: ما فوقها يستهلك
خدمات 011 عبرها حصرًا، وما تحتها لا يعرف شيئًا عن الـharness.

### 2. القراران المحفوظان (بنيويًا لا شعاريًا)

| القرار | أين يُفرض |
| --- | --- |
| لا أدوار حرة — تواصل عبر العقود حصرًا | `RoleRuntime` يرفض طلبًا/نتيجة خارج عقد الدور (TypeError) |
| المنسق ليس LLM | `coordinator.classify_tick` دوال نقية + جدول `JOB_TRANSITIONS` مقفل |

## سلسلة القبول (معيار القبول الحرفي)

```
Owner → Objective → Coordinator → Plan → Approval → Preflight →
EngineeringJob → Role → Tool/Capability → Evidence → Verifier →
Arbiter → Checkpoint → Restart → Resume → Audit → Owner
Verification → VERIFIED
```

لكل مرحلة من الثماني حالة حتمية مشتقة من الأحداث الدائمة وحدها
(`GET /api/projects/{id}/chain`): PENDING / ACTIVE / DONE /
WAITING / FAILED. المسار يتوقف بأمان عند أي نقطة:

| التوقف | متى | مسار الرفع |
| --- | --- | --- |
| WAITING_CAPABILITY | مزود/قدرة غير جاهزة (LLM، بحث…) | جهّز المزود ← اختبره ← أعد الفحص/الاستئناف |
| WAITING_WORKER | لا بيئة تنفيذ موافقة للسياسة | أضف بيئة (عامل Linux/WSL2 أو ركيزة) ← تحقق ← أعد الفحص ← استئناف |
| WAITING_GATE | قرار مالك معلق (اعتماد/مراجعة/تحقق نهائي) | عالج البوابة من صفحة المشروع |
| RETRYING | فشل عابر ضمن الميزانية | تلقائي — الحلقة تكمل |
| REVISING | خطة تُراجع بسياق الفشل | موافقة على الخطة v الجديدة |
| INTERRUPTED | وفاة العملية أثناء الدوران | استئناف صريح من آخر checkpoint |

كل انتظار يحمل **نوعه وسببه الحرفي ومسار رفعه** — لا «محجوب»
عائمة أبدًا.

## الوظيفة الداملة EngineeringJob

- صف واحد لكل تشغيل/استئناف متصل؛ التشغيل بعد انتظار يعيد الصف
  نفسه («توقف بأمان ← استؤنف»)، والحالة النهائية وحدها تفتح صفًّا
  جديدًا.
- **النبضة**: `heartbeat_at` يتحدث كل tick — برهان حياة لا انطباع.
  في الواجهة نقطة نابضة خضراء للوظيفة العاملة، صفراء لتقادم النبضة،
  حمراء للمقاطعة.
- **الاكتمال قرار المالك وحده**: إعادة تشغيل مشروع «مرشح» تعيد
  WAITING_GATE لا COMPLETED.
- **الاسترداد عند الإقلاع**: ما كان يدور لحظة وفاة العملية يُوسم
  INTERRUPTED (لا حياة كاذبة)؛ الانتظارات تبقى كما هي (لا شيء ضاع).
  لا تنفيذ عشوائي عند الإقلاع أبدًا — الاستئناف قرار صريح.

## نقاط API الجديدة

| النقطة | الغرض |
| --- | --- |
| `GET /api/harness/roles` | الأدوار الخمسة + العقود + الربط الحي وجاهزيته |
| `GET /api/harness/capabilities` | الكتالوج الموحد (نمط الحل + المزودون + تصنيف الانتظار) |
| `GET /api/harness/events/vocabulary` | المفردة القانونية + خريطة canonical |
| `GET /api/harness/jobs[/{id}]` | الوظائف الدائمة ودفاترها |
| `GET /api/projects/{id}/job` | أحدث وظيفة للمشروع |
| `GET /api/projects/{id}/timeline` | الخط الزمن المرحلي (إسقاط قراءة) |
| `GET /api/projects/{id}/chain` | سلسلة القبول بحالاتها |

## في الواجهة

- **بطاقة الوظيفة** (بعد بطاقة بوابة التنفيذ): الحالة العربية،
  النبضة، النبضات/checkpoints/الإعادات، الانتظار بنوعه وسببه
  وإجراء المالك ومسار الرفع، الدور الحالي.
- **سلسلة القبول**: المراحل الثماني كخطوات بحالاتها + أول مرحلة
  منتظرة بسببها الحرفي.
- **الخط الزمني المرحلي**: من الإسقاط — كل حدث بمرحلته وفاعله
  (المالك/المنسق/المفكر/المنفذ/المراجع/المحكَّم).
- كل ذلك يتحدث لحظيًا عبر تيار أحداث 011 العام (JOB_* في
  REFRESH_KINDS) بلا refresh يدوي.

## ما لم يُنقل من فكرة الـHarness العامة (قرار موثق)

- **Skills**: خارج نطاق 012 (ليست في ترتيب مراحله) — البنية
  تستقبلها لاحقًا عبر درزة جديدة دون لمس هذه الطبقة.
- **فرق وكلاء أحرار**: مرفوضة بنيويًا — الأدوار الخمسة بعقود
  حصرًا (القرار 1).
- **منسق LLM**: مرفوض بنيويًا (القرار 2).
