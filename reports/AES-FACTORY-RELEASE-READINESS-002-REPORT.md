### الجذر المؤكد بالأدلة الحية من العدّاء (لا تخمين)

1. `unshare(CLONE_NEWUSER)` **ينجح** على العدّاء (ثبّته المسبار الحقيقي §2).
2. ثم كتابة `/proc/self/setgroups` (لتعطيل setgroups قبل خرائط uid/gid)
   تُرفض بـ **EACCES (13)** — لا EPERM: هذا **وسم AppArmor** لا منطق نواة.
3. البصمة مطابقة حرفيًا للسياسة المعروفة في Ubuntu 24.04+:
   `kernel.apparmor_restrict_unprivileged_userns=1` — «الـ userns يُنشأ لكن
   القدرات داخله لا تأتي معه»، فتُرفض كتابات procfs. الحالة موثقة علنًا
   (yocto «Error on Ubuntu 24.04 while writing to /proc/self/setgroups»،
   binpash/try#198، ومقال 2026-11-05 بنفس العنوان التقني).
4. ubuntu-latest (Nov 2026) = Ubuntu 24.04+ ⟶ الركيزة المعزولة للمنتج
   لا تستطيع البدء على العدّاء مهما كان الكود صحيحًا.

### الإصلاح الجاهز وحاجزه الوحيد

الإصلاح = خطوة توافق بيئة واحدة (نفس فئة تثبيت bubblewrap الموجود أصلًا
في الـ workflow):

```yaml
      - name: Align runner kernel for unprivileged user namespaces
        run: |
          echo "before: $(cat /proc/sys/kernel/apparmor_restrict_unprivileged_userns)"
          sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
          echo "after:  $(cat /proc/sys/kernel/apparmor_restrict_unprivileged_userns)"
```

- **لا تعطيل اختبار، لا تحويل فشل إلى تخطٍ، لا تخفيف أمني:** عزل الرمل
  الداخلي (seccomp داخل الرمل، إسقاط القدرات capset، rlimits، الجذور
  للقراءة فقط، بلا شبكة) يبقى مفعّلًا كاملًا؛ الـ sysctl يعالج سياسة
  العدّاء المؤقت لا المنتج.
- **حاجز وحقيقي:** الالتزام بهذا التغيير محجوب — رمز المالك الممنوح
  يحمل `X-OAuth-Scopes: read:user, repo` **بلا `workflow`**، وgit push
  يُرفض (`refusing to allow a Personal Access Token to create or update
  workflow ... without 'workflow' scope`) وContents API يعيد 403 (مُثبت
  عمليًا). التغيير جاهز مُلتزمًا محليًا (`4b427d8` على `factory/rr002-work`)
  وجاهزًا للنسخ من هذا القسم. **لم يُحاول تجاوز الحاجز بأي مسار جانبي**
  (Git Data API أو غيره) — احترامًا لحدود الصلاحية.
- **التحقق المحلي الموازي:** المجموعة الموثوقة كاملة تعمل خضراء على مضيف
  بلا قيد AppArmor (راجع §7 أدناه للنتيجة الرقمية).

## §8 — أوامر التشغيل والإيقاف والفحص + الحكم

### أوامر قابلة للتكرار (ملفات في `scripts/` بالفرع)

```bash
bash scripts/server_start.sh     # أمر واحد: يبني venv/يُثبت ما يلزم إن غاب،
                                 # يطلق uvicorn منفصلًا (setsid)، يكتب
```

- لا تهيئة داخلية يدوية: كل ما يلزم هو الأمر نفسه.
- الحالة كلها في `runtime/` (SQLite + ملفات المخرجات) — القابل للنسخ
  لبيئة أخرى بنسخ هذا المجلد.

### الحكم النهائي

(مستودع نظيف، دورة UI كاملة حية بمخرَج قرص حقيقي، استمرارية موثقة،
أدلة بصرية خام مفتوحة) **مُثبت ومُسلَّم**، لكن شرط القبول «المجموعة
الموثوقة خضراء على GHA في الالتزام النهائي» غير متحقق — والسبب ليس
في الكود ولا في المنتج بل في سياسة عدّاء التشغيل، والإصلاح جاهز
بسطر واحد محجوب فقط بنطاق رمز الدفع.

دفع فارغ لإعادة التشغيل):

2. المالك يمنح رمزًا بنطاق `workflow` فيُدفع الالتزام الجاهز `4b427d8` كما هو.
