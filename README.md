# Agentic Engineering System

نظام هندسة ذاتي بإشراف المالك: هدف ← خطة رئيسية ← حلقة ذاتية دائمة
(تنفيذ ← اختبار ← مراجعة ← تدقيق ← تحكيم ← الخطوة التالية) ← أدلة ←
بوابات مالك ← تحقق نهائي. ومعه منتج المحادثة اليومي: محادثة بسيطة
ومهمة بدورة الأدوار الخمسة — كلاهما حي فعليًا، **لا mock في أي مسار
إنتاج أبدًا**.

> **الاسم الرسمي (الأمر 007 §1): Agentic Engineering System** — كان
> «Agent Hub v2». مسارات الكود والمستودع المحلي (`agent-hub-v2/`)
> بقيت كما هي عمدًا؛ إعادة تسمية مستودع GitHub تتطلب إجراء المالك.

> **الحالة الحالية: الأمر 010 — بيئات تنفيذ حقيقية + استمرارية المحادثة + معمارية الواجهة (v3.2.0).**
> المشروع كيان أول: خطة رئيسية versioned تعتمد من المالك، مراحل
> وخطوات بحالات صادقة، تنفيذ دائم بمزوده ونموذجه، أدلة مرتبطة
> بالمعرفات، تدقيق ميكانيكي (لا ثقة بنص المنفذ)، إعادة/مراجعة
> موثقة، نقاط استئناف تنجو من إعادة تشغيل العملية، بوابات مالك
> للقرارات الجوهرية حصرًا، وتحقق نهائي قرار المالك وحده. وإدارة
> مزودين كاملة من الواجهة. **والآن: بيئات تنفيذ قابلة للتسجيل
> والتحقق (محلية + عامل بعيد حقيقي عبر HTTP)، وبحث قابل للتوفير
> (DDG/SearXNG/API)، ومحادثة بهوية دائمة (`conversation.bind` أول
> حدث + توجيه `#/chat/{id}`)، وواجهة بتبويبات وحدود أخطاء وحالات
> كاملة.**

## ما يميز النظام

| الجانب | v1 (agent-hub) | هذا النظام |
| --- | --- | --- |
| النطاق | مهمة واحدة في الذاكرة | **مشروع دائم**: خطة ← مراحل ← خطوات ← تنفيذات ← أدلة ← تدقيق |
| الحقيقة | حالة العملية الحية | **القاعدة** (SQLite) — استرداد بعد restart بلقطة |
| التدقيق | تقرير المنفذ النصي | **مقارنة ميكانيكية**: مخطط ↔ منفذ ↔ مختبر ↔ مُثبت |
| الفشل | توقف | **تشخيص ← إعادة ← بوابة مالك ← مراجعة خطة v+1** |
| الموافقات | تصنيف نصي بلا توقيع | منح موقعة HMAC + بوابات مالك للقرارات الجوهرية حصرًا |
| التنفيذ | Popen مباشر على المضيف | **ركيزة عزل أصلية**: namespaces + seccomp + rlimits + watchdog |
| المزودون | قائمة مغلقة في الكود | **سجل دائم قابل للإدارة** من الواجهة (CRUD + جاهزية) |
| بيئة التنفيذ | مسبار مستقل عن المنفذ (تناقض ممكن) | **مصدر واحد** (resolve_executor) — المسبار = المنفذ + هوية البيئة في كل نتيجة |
| البحث | DDG وحده = «الإنترنت» | **مزودون قابلون للتوفير** (DDG/SearXNG/API) بفشل مفصل لكل مزود |
| المحادثة | هوية تضيع بين الرسائل | **conversation.bind أول حدث** + توجيه دائم + استرداد بعد التحديث |
| الواجهة | كومة حقول وشاشات صامتة | **ستة تبويبات + حدود أخطاء + حالات loading/error/empty** |
| التجربة | متمركزة حول الخطة | **محادثة حديثة** (＋ محادثة/مهمة) + **عرض مشاريع** كامل |

## المبادئ الخمسة

1. **الصدق قبل الراحة** — لا SUCCESS وهمية؛ الحالات الصادقة والفشل الصريح.
2. **الأدلة قابلة للفحص** — sha256 لكل ملف، وكل استدعاء موثق.
3. **العزل قبل التنفيذ** — لا كود على المضيف أبدًا؛ الركيزة أو لا تنفيذ.
4. **المالك يقرر الجوهري** — اعتماد الخطة، مراجعتها، التحقق النهائي؛
   والباقي تلقائي.
5. **القاعدة مصدر الحقيقة** — لا حالة في الذاكرة تضيع بإعادة تشغيل.

## البنية السريعة

```
src/
├── api/            # نقل نحيف: محادثة/مهمة/مشاريع/مزودون/إعدادات
├── execution/      # بيئات التنفيذ: خلفيات حقيقية + سجل + تحقق + موحّد المنفذ
├── research/       # مزودو البحث القابلون للتوفير (ddg/searx/api)
├── core/           # المنسق (نحيف) + الإيقاف الآمن + التركيب
├── roles/          # الأدوار الخمسة الحية (برومبت ← LLM ← عقد صارم)
├── router/         # الموجّه + حزم الحماية + ربط الأدوار الدائم
├── workflow/       # ★ نواة المشروع: محرك الحلقة الذاتية + المخطط
│                   #   + المدقق الميكانيكي + الكيانات الدائمة
├── providers_registry/  # ★ سجل المزودين: CRUD + تكوينات + مسبار جاهزية
├── persistence/    # SQLite: محادثات + workflow + مزودون (17 جدولًا)
├── substrate/      # ركيزة العزل (namespaces + seccomp)
├── eoe/            # محرك الأوامر التنفيذية (منح موقعة + دفع بموافقة)
└── ui/             # واجهة عربية RTL: محادثة + مشاريع + إعدادات
```

## التشغيل

```bash
python -m venv .venv && .venv/bin/pip install -e ".[test,pdf]"
.venv/bin/python -m uvicorn api.routes:app --port 8010
# أو على Windows: .\scripts\setup.ps1 ثم .\scripts\run.ps1
```

ثم افتح <http://127.0.0.1:8010> — المحادثة فورية، والمشروع من زر
＋ في قسم «المشاريع» بالشريط الجانبي.
